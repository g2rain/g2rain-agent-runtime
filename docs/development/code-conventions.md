# 代码规范

- 保持 `startup -> biz -> api` 依赖方向；不以便利为由跨层引用实现。
- 领域状态、节点迁移和副作用必须使用明确类型表达，避免以散落字符串隐式约定。
- Controller 只完成协议适配；业务决策放在 Service/Domain；持久化隔离在 DAO。
- 新增运行时状态、事件、工具或恢复动作时，必须同步更新状态、事件或契约文档。
- 日志和异常信息应使用关联 ID，且不得输出提示词全文、密钥、Token 或工具敏感参数。

## 编码细则（手写代码必须遵守；生成代码保持生成器原样）

### 技术选型

- 工具优先级：JDK 25 → g2rain-common → Spring → 自己写的工具方法。前三者都没有合适的，先说明原因再写。
- 只在 runtime 内部用的工具方法放到 `RuntimeUtils`，不要加进 g2rain-common。

### 写法

- 判空用 `Objects.isNull` / `Objects.nonNull`，不写 `== null` / `!= null`。
- 不用递归（有栈溢出风险），改成循环或显式栈。
- 不散落字面量 key（Map 键、Hash 字段、固定取值集合），统一用常量或枚举。
- 不写嵌套的三元表达式。
- 循环写法：
  - 只遍历元素、不用下标时，用增强 for：`for (KeyTtl renewal : renewals)`。IDEA 提示 `'for' loop can be replaced with enhanced 'for'` 时，必须改成这种写法。
  - 确实需要下标时（倒序、按下标取另一个列表、跳步），才用下标循环，并先缓存 size：`for (int i = 0, j = list.size(); i < j; i++)`，不能在条件里写 `i < list.size()`。
- 代码必须没有 IDEA 检查告警，包括可空性、恒真/恒假条件、常量参数。
- 类名、方法名、属性名、变量名、包名要准确、简洁，不要过长；名字和行为不符属于缺陷。

### 异常

- 使用标准异常体系：抛 `BusinessException` 加上 `RuntimeErrorCode` 中的错误码，参数用具名参数，文案由 Infra 的 i18n 提供。
- 不硬编码报错文案，也不用字符串拼接错误详情。

### 注释

- 手写类型的类 Javadoc 末尾依次写 `@author alpha`、`@since <创建日期>`，日期格式如 `2026/11/22`。
- 注释和 Javadoc 只描述当前行为，不写“参照了某某系统”“对标了某某”之类的来历。
- 示例中不得出现真实公司名或真实的客户、业务数据，用中性的占位（如“示例”“A”）。
- 新建包时，`package-info.java` 要加 `@NullMarked`（jspecify）。

### 范围

- 只实现已经约定的内容，不自行增加行为或限制。
- 不写兼容旧行为或旧数据的代码，也不写迁移逻辑。
- 任务卡没有列出的类不改；如果必须改，先停下来说明原因。
- 改完交回，由开发者自己编译和测试，不执行构建、打包或部署。
